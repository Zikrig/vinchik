## 1. Цель продукта

Telegram-бот знакомств для аудитории Таджикистана с анкетами, симпатиями (уведомление и список лайкнувших со ссылками), обязательной подпиской на рекламные каналы (для бесплатных пользователей), платным Премиум и админ-панелью.

Ожидается **высокая нагрузка** после запуска рекламы у блогеров — архитектура и деплой должны это учитывать.

## 5. Языки и UX-правила интерфейса

### 5.1. Языки

1. При первом `/start` — выбор языка: **Русский** / **Тоҷикӣ**.
2. Дальше смена языка — только в **⚙ Настройки** главного меню (§8.5).
3. Все сообщения, кнопки, ошибки, уведомления — на выбранном языке.
4. Язык сохраняется в профиле.
5. Админ-панель — на русском.

### 5.2. Кнопки

- **Все кнопки — inline**, без нумерации в тексте (`1.`, `2.` и т.п. запрещены).
- Подписи **лаконичные** (как в Дайвинчике), без канцелярита.
- **Исключение:** шаг «Откуда ты» — Telegram умеет запросить геолокацию только через **reply-кнопку** «📍 Отправить местоположение». Рядом по возможности inline «Оставить текущее» (если локация уже есть). После получения локации reply-клавиатуру убирать.

## 6. Регистрация и анкета

### 6.1. Старт

Команда `/start`:
- новый пользователь → язык → мастер анкеты;
- анкета уже есть и активна → меню анкеты (§7) или продолжение с места остановки FSM;
- soft-launch (§12) → после анкеты заглушка вместо ленты.

### 6.2. Порядок шагов мастера (первичное заполнение и «Заполнить заново»)

| # | Шаг | UI | Правила |
|---|-----|-----|---------|
| 1 | Возраст | текст | 16–99; если значение уже есть — кнопка **Оставить текущее** |
| 2 | Пол | inline | Парни / Девушки (или Мужской / Женский — согласовать формулировку) |
| 3 | Кто интересен | inline | Девушки / Парни / Всё равно |
| 4 | Откуда ты | reply: геолокация | `location` (lat/lon); reverse-geocode → город для карточки; если уже есть — **Оставить текущее** |
| 5 | Как мне тебя называть? | текст | имя, 2–32 символа; можно **Оставить текущее** |
| 6 | О себе | текст | описание + кого ищет / чем заняться; лимит ~500–900 символов; кнопки **Пропустить** / **Оставить текущее** (если текст уже был) |
| 7 | Фото | photo | видят другие; **Оставить текущее**; иначе новое фото |

После **успешного последнего шага** (фото) пользователь **сразу попадает в ленту** — показывается первая подходящая анкета (не отдельное «меню успеха»), если не soft-launch.

То же при нажатии **Смотреть анкеты** из меню анкеты.

### 6.3. Валидация фото

- Принимаем как Telegram **Photo**, так и изображение-документом при необходимости.
- Допустимые форматы: **JPEG / PNG / GIF** (по MIME / расширению).
- Размер файла **≤ 5 МБ** (проверка через `getFile` / размер из апдейта).
- Иначе — ошибка и повтор запроса фото.
- В БД храним `file_id` (и при необходимости `file_unique_id`).

### 6.4. Username и «кликабельность» профиля

Чтобы в списке симпатий была кликабельная ссылка `t.me/<username>`, у пользователя должен быть задан `@username` в Telegram.

Bot API настройки приватности не читает — смотрим только поле `username` в апдейте.

**Без отдельной кнопки «Проверить»** (лишний непонятный шаг):

1. Если `username` уже есть — тихо сохраняем, ничего не спрашиваем.
2. Если нет — коротко просим задать имя пользователя в настройках Telegram и **просто продолжить** (написать что угодно / нажать «Далее» / снова `/start`). Проверка встроена в следующий апдейт: появился `username` → идём дальше; нет — мягко повторяем ту же просьбу.
3. Отдельных «Проверить / Обновить статус» в UI нет.
4. Ручной ввод контакта текстом вместо `@username` не делаем.

## 7. Меню после анкеты («Моя анкета»)

Показ своей карточки (фото + текст в формате ленты) и **только inline**:

| Кнопка | Действие |
|--------|----------|
| Заполнить заново | Полный мастер §6.2 (с «Оставить текущее» на шагах) |
| Изменить фото | Только шаг фото |
| Изменить текст | Только описание (шаг «О себе»); при необходимости уточнить: только описание или имя+описание |
| Смотреть анкеты | Сразу лента, первая анкета |

Язык и прочие настройки — не здесь, а в главном меню через **⚙** (§8.5).

## 8. Просмотр анкет (лента)

### 8.1. Формат карточки

Фото + подпись:

```text
{Имя}, {возраст}, {город}
{описание}
```

Пример:

```text
Настя, 19, Москва
Мне скоро 21.
В москве первый раз, ищу с кем погулять.
Я высокая, 180. Отношений не ищу.
```

Город — из reverse-geocode по сохранённой геолокации (или кэш `city_name` в профиле).

### 8.2. Кому показывать

Показывать анкету B пользователю A, если:
1. анкета B **активна** (`is_active`);
2. пол B ∈ «кто интересен» A;
3. пол A ∈ «кто интересен» B (взаимно; «всё равно» = любой);
4. A ещё не оценивал B (лайк / дизлайк / сообщение-оценка — см. ниже);
5. A ≠ B;
6. поиск: диагональ радиус×возраст — волна 0: 10 км ±2; волна 1: 10 км ±5 и 25 км ±2; волна 2: 10 км ±10, 25 км ±5, 50 км ±2; и т.д. Каждый показ пересчитывается с нуля. Внутри волны — премиум / меньшая |Δвозраст| / ближе км; дальше — заглушка «нет больше пар…»; реактивация через 1 / 3 / 7 суток после последней активности (не чаще).

### 8.3. Приоритет показа (Премиум)

Анкеты с активным Премиум чаще попадают в выдачу (весовой приоритет / interleaved).

### 8.4. Кнопки под анкетой (inline, без цифр)

Ряд 1: ❤️ · 💌 · 👎  
Ряд 2: ⚠️ · ⭐ · 🚪

| Кнопка | Действие |
|--------|----------|
| ❤️ / Лайк | Симпатия; лимит; уведомить получателя (§8.7); следующая анкета |
| 💌 | Сообщение + симпатия; всем; тратит лимит у мужчин без Премиум |
| 👎 / Дизлайк | Скип; следующая анкета |
| ⚠️ | Жалоба |
| ⭐ | Премиум |
| 🚪 | Выход из ленты → **меню паузы** (§8.5) |

### 8.5. Главное меню (после 🚪 и как хаб)

Не нумеровать кнопки. Состав:

| Кнопка | Действие |
|--------|----------|
| Смотреть анкеты | Снова лента |
| Моя анкета | §7 |
| ⭐ Премиум | Тарифы / покупка |
| ⚙ / Настройки | Подменю: выбор языка (Русский / Тоҷикӣ), позже другие опции при необходимости |
| Больше не ищу | Подтверждение отключения (§8.6) |

Опционально (по желанию заказчика):
- ✈️ Поделиться ботом

**Настройки:** после выбора языка — короткое подтверждение и возврат в главное меню (или в настройки). Отдельной кнопки «Язык» в корне меню нет — только через шестерёнку.

### 8.6. Отключение анкеты

Текст в духе:  
«Так ты не узнаешь, что кому-то нравишься… Точно отключить анкету?»

Кнопки (лаконично, без цифр):
- Да, отключить  
- Нет, назад  

При «Да» → `is_active = false`, анкета пропадает из чужих лент. Включить снова — из «Моя анкета» / «Смотреть анкеты» (с реактивацией).

### 8.7. Входящие симпатии (без ожидания взаимного матча)

**Матч ждать не нужно.** Контакты — через список лайкнувших.

#### Уведомление (батч, не чаще 1 раза в 30 минут)

`N` = число **последних** (ещё не показанных в списке / накопившихся к моменту пуша) симпатий — не отдельное сообщение на каждого.

Примеры текста:

| Ситуация | Текст | Кнопка |
|----------|--------|--------|
| Первая пачка, N = 1 | Вы кому-то понравились! | Посмотреть |
| Позже накопилось, N = 3 | Вы кому-то понравились! (3) | Посмотреть |

Правила:

1. Частота пуша получателю — **не чаще одного обновления в 30 минут**. Промежуточные (2-я симпатия и т.д.) не шлём отдельным сообщением: к следующему слоту пишем сразу актуальное `N` (например, пропустили «двое» → сразу «(3)»).
2. При новом уведомлении у **предыдущего** сообщения кнопку **Посмотреть** убираем (`editReplyMarkup` / снятие клавиатуры), чтобы не плодить несколько активных «Посмотреть».
3. На актуальном сообщении — одна кнопка **Посмотреть**.
4. При N = 1 скобки `(1)` не обязательны (как в примере без числа).
5. По **Посмотреть** — список последних симпатий: кликабельные `t.me/username` (+ имя и т.п.). После просмотра счётчик «последних» для следующего батча сбрасывается / сдвигается.
6. Взаимный лайк для показа ссылки не нужен.

Реализация: у пользователя хранить `last_like_notify_at`, `likes_notify_message_id`, накопитель непросмотренных входящих; при лайке — либо отложить до окна 30 мин, либо сразу отправить/обновить, если окно прошло.

Массовых рассылок нет.

### 8.8. Пустая лента

«Пока никого нет, загляни позже» / soft-launch заглушка (§12).

## 10. Премиум

### 10.1. Тарифы (настраиваемые админом)

По умолчанию:
- 2 дня;
- 7 дней;
- 30 дней.

У каждого тарифа: название, срок (дни), цена (текст/число для отображения).

### 10.2. Покупка (ручная оплата)

1. Пользователь выбирает тариф.
2. Бот показывает **контакты менеджера** и инструкцию по оплате (+ идентификатор заявки).
3. Создаётся заявка со статусом `pending`.
4. Админ/менеджер **подтверждает оплату** в админ-панели → подписка активируется автоматически до `now + N days`.
5. Пользователь получает уведомление об активации.

Отклонение заявки — опционально (кнопка «Отклонить» + уведомление пользователю).

### 10.3. Преимущества Премиум

| Преимущество | Поведение |
|--------------|-----------|
| Приоритетный показ | Анкета чаще в ленте у других |
| Без обязательных каналов | Проверка подписки не применяется |
| Без лимита лайков | Дневной лимит не действует |

### 10.4. Окончание подписки

- Фоновая задача (или проверка при действиях): если `premium_until < now` → Премиум выключен.
- Пользователь снова попадает под правила бесплатной версии.

### 10.5. Ручная выдача

Админ может выдать/снять Премиум вручную (по `user_id` / из списка).

## 11. Бесплатная версия и ограничения

### 11.1. Обязательные каналы

- Список каналов настраивается в админке (channel id / @username).
- Перед доступом к ленте (и при необходимости к другим действиям) бесплатный пользователь должен быть подписан на **все** обязательные каналы.
- Если не подписан → сообщение + кнопки «Подписаться» + «Проверить».
- Пользователи с активным Премиум проверку **не проходят**.

### 11.2. Лимит лайков

| Кто | Лимит |
|-----|-------|
| Мужчины без Премиум | Дневной лимит (число задаёт админ, по умолчанию согласовать, напр. 10–50) |
| Женщины | **Лимита нет** (договорённость с заказчиком) |
| Любой с Премиум | Лимита нет |

При исчерпании лимита — сообщение с преимуществами Премиум и кнопкой «⭐ Премиум»; скипы лимит не расходуют.

Сброс лимита: по календарным суткам **UTC**. При исчерпании лимита нельзя **смотреть анкеты** до конца суток UTC.

## 12. Soft-launch (режим «только регистрация»)

Договорённость: в первый период бот может **только регистрировать** анкеты.

| Режим | Поведение |
|-------|-----------|
| `registration_only = true` | Регистрация работает; «Смотреть анкеты» недоступно или показывает заглушку |
| Заглушка | Текст вроде: «Спасибо за регистрацию! Напишем, когда появятся анкеты» |
| Включение/выключение | Флаг в админке или в `.env` (`REGISTRATION_ONLY=true/false`) |

После накопления базы админ переключает режим → открывается лента.

Импорт стартовых анкет (если заказчик соберёт данные отдельно) — опционально, не блокер MVP.

## 13. Админ-панель

Доступ: список `ADMIN_IDS` в `.env`.

Функции:

1. Подтверждать / отклонять заявки на оплату Премиум.
2. Выдавать / отключать Премиум вручную.
3. Изменять тарифы (срок, цена, активность).
4. Управлять обязательными каналами (добавить / удалить / список).
5. Изменять дневной лимит лайков (для мужчин без Премиум).
6. Просматривать пользователей с активным Премиум.
7. Включать/выключать режим «только регистрация».
8. (Желательно) статистика: пользователей, анкет, симпатий за сутки — если успевает в срок.

Интерфейс: (A) команда `/admin` + inline; (B) веб-админка (FastAPI) — каналы, лимит, радиус, soft-launch, заявки Премиум.

## 14. Модель данных (минимум)

### users
- `tg_id` (PK)
- `username` (нужен для ссылки; обновлять при активности)
- `language` (`ru` / `tg`)
- `role` (user / admin)
- `premium_until` (nullable datetime)
- `last_like_notify_at`, `likes_notify_message_id` (батч §8.7)
- `created_at`, `updated_at`

### profiles
- `user_id` (FK, unique)
- `name`, `age`
- `city_name` (из reverse-geocode, для карточки)
- `lat`, `lon` (геолокация)
- `gender` (male / female)
- `looking_for` (male / female / any)
- `description` (nullable)
- `photo_file_id`
- `is_active` (bool) — выкл. через «Больше не ищу»
- `created_at`, `updated_at`

### likes
- `from_user_id`, `to_user_id`
- `action` (like / dislike / message)
- `message_text` (nullable, для 💌)
- `is_seen` (видел ли получатель в «Посмотреть»)
- `created_at`
- unique(`from_user_id`, `to_user_id`)

Таблица `matches` в MVP **не нужна**. Outbox — только если понадобится на пике для точечных «понравились» / Премиум; массовых рассылок нет.

### premium_orders
- `id`, `user_id`, `plan_id`
- `status` (pending / approved / rejected)
- `created_at`, `processed_at`, `processed_by`

### premium_plans
- `id`, `title`, `days`, `price_text`, `is_active`

### required_channels
- `id`, `channel_id`, `title`, `invite_link`, `is_active`

### settings
- `key`, `value`  
  (например: `daily_like_limit`, `registration_only`, `manager_contact`)

### like_counters (или агрегация по likes)
- учёт лайков за сутки для проверки лимита

## 15. Нефункциональные требования

1. **Конкурентность:** корректная работа при параллельных действиях (уникальные лайки) — транзакции / unique constraints.
2. **Антифлуд:** middleware на частые нажатия.
3. **Логирование:** ошибки в лог; падения хендлеров не роняют процесс.
4. **Секреты:** токен и доступы только в `.env`, не в git.
5. **Инструкция:** `instructions.readme` — установка на Ubuntu/Debian, Docker, переменные окружения, бэкап БД.
6. **Стабильность:** бот поднимается через `docker compose up -d` и переживает рестарт контейнера.

## 17. Критерии приёмки

1. Мастер анкеты ок; username — без кнопки «Проверить», встроенная проверка на следующем шаге/апдейте.
2. Фото: форматы + ≤5 МБ.
3. После анкеты / «Смотреть анкеты» — сразу лента.
4. Симпатии: батч-текст «понравились» / «понравились (N)», не чаще раза в 30 мин; старая кнопка Посмотреть снимается; список последних со ссылками.
5. 🚪 → меню паузы; отключение анкеты с подтверждением.
6. Без повторов оценённых; без обязательного взаимного матча.
7. Премиум, каналы, лимиты, soft-launch, админка — по §§10–13.
8. ru/tg; деплой по инструкции.
